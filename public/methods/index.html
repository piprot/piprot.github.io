方法库

把用得上的框架，摆到台面上

十二条方法卡，按「营销业绩 / 管理数字化 / 咨询决策」分组。每条都按「什么时候用 / 怎么用 / 用错会怎样」展开：先确认场景，再看动作，最后看边界。框架是工具，不是结论——用得对不对，比记不记得住更要紧。

A · 营销业绩提升

把成交拆成可练的动作

这一组整理自销售与业务研究笔记，已去掉行业专属话术与客户信息，只留通用框架。

A01 / 流程

需求导向销售五环与成交四要素

什么时候用开始接触一位新客户，或成交率忽高忽低、说不清卡在哪一步时，用来逐环对照。

怎么用按约访 → 接触 → 方案 → 异议 → 促成五环走一遍，看哪一环没走完；四要素贯穿全程：信任是前提、需求是基础、帮助与价值是关键，急迫性只管临门一脚。

用错会怎样跳过信任与需求直接讲产品，异议就会变成反复压价；把急迫性当主推手段，这次就算成了，也难有下一次。核心竞争力落在专业度与服务，不在价格让步。

A02 / 异议

异议处理五步法

什么时候用客户提出反对意见、开始挑细节，或者反复追问却迟迟不下决定时。

怎么用按倾听 → 认同 → 澄清 → 转换 → 促单五步走，先让对方把话说完，再判断异议属于信任、需求未挖掘、方案不匹配、不急迫中的哪一类；处理完顺势回到促成。

用错会怎样一听反对就急着辩解或让步，等于把兴趣信号当成拒绝，也跳过了真正的原因；处理完不回到促成，谈话就会停在一连串解释里。

A03 / 节奏

促成的 40 / 30 / 20 / 10

什么时候用成交总靠临门强推，或一次面谈里产品讲得很多却推不动时，用来检查时间都花在了哪。

怎么用把一次完整沟通大致分成四段：约四成建立信任、三成做观念培养与需求激发、两成讲产品，促成本身只留一成；先对照实际分配，再决定该砍哪一段。

用错会怎样大头时间都花在讲产品和催签，前三段没做实，促成就会变成反复施压。这组比例是诊断用的参照，不是能直接套用的脚本，硬套反而会打断对话节奏。

A04 / 表达

FABE 价值翻译

什么时候用写方案、做产品介绍，或对方听完只回一句「所以呢」的时候。

怎么用每个功能都往下追一句「这对对方意味着什么」，一直追到对方能自己算出来的结果；用差距与收益说话，不堆参数。

用错会怎样停在功能罗列，对方看不到和自己有关的部分；或者把收益写成没有依据的承诺，一被追问就站不住——翻译的前提是算得出来。

A05 / 诊断

QuickStar 四步法

什么时候用面对复杂、跨领域、对方自己还没把问题说清楚的咨询场景。

怎么用调频道进入对方的处境，沿三层把风险穿透找到真问题，用专业信息点破认知盲区，最后才给方案；把大部分时间留在前段的诊断上。

用错会怎样一上来就给方案，等于用自己的框架盖住对方的真实处境；诊断不足时，方案写得越完整，越容易偏题。

A06 / 复盘

五步复盘法

什么时候用一轮沟通结束，或结果不如预期、需要回头看过程时。

怎么用按风险共识 → 现状分析 → 再平衡 → 回到目标 → 讨论下一步这五步走一遍，重点守住顺序：先对齐风险认知，再谈具体动作。

用错会怎样直接从「接下来配什么」开始，共识和目标都没对齐，讨论就变成一轮轮改方案。这套方法可迁移的是次序，不在于沿用原本的业务术语。

B · 管理数字化

先理流程，再谈工具

这一组整理自公开资料，只做要点索引，不转载原文。

B01 / 流程

流程化思维

什么时候用同一件事反复出错、换个人做结果就变，或者交接总靠口头交代时。

怎么用把任务拆成有序步骤，标清每个节点的输入、负责人与判定规则，再看结果能不能被预测、被交接、被复制。

用错会怎样只画流程图不改规则，异常还是会绕回原来那个人；把步骤拆得过细，一线失去判断空间，反而没人愿意用。

B02 / 沉淀

知识库两层结构

什么时候用资料越存越多、想找找不到，或同一份内容出现好几个版本时。

怎么用主目录只留「资料」与「总结」两层：前者放原始解析内容，后者放整理后的结构化结论；按主题分类、去重合并出清单，人工确认后才入库。

用错会怎样原始材料与结论混着放，过一阵就分不清哪句是事实、哪句是判断；没有人工确认就自动入库，错误也会被反复引用。

B03 / 复用

对话—沉淀—复用闭环

什么时候用同类问题反复问、每次都从头开始，或换个人就接不上的时候。

怎么用每次对话后把有效信息提成结构化单页回存；新任务先检索历史案例与方法，再出方案，让上一轮的结论成为这一轮的起点。

用错会怎样只存不检索，知识库会变成另一个没人看的文件夹；把单次提速当成价值，就会跳过沉淀，下一轮照样从零开始。

C · 咨询与决策

把纠结变成能算的题

这一组用来把判断从感觉拉回到能写下来、能被追问的结构上。

C01 / 取舍

ROI 科学决策三角形

什么时候用两个选项各有好处、反复摇摆，或者争执只集中在某一个数字上时。

怎么用宽度上列清关键收益项与成本项，深度上给优先级、能量化的量化，高度上放回长期视角再看一次；三个维度分开写，别混进同一张利弊表。

用错会怎样只比一个最容易算的数字，长期代价就被漏掉；或者什么都想量化，把判断伪装成精确，反而更难做决定。

C02 / 盘点

资源盘点九维

什么时候用定计划、做转型、接新任务之前，尤其当目标是别人给的、自己心里没底时。

怎么用把时间、财产、认知、工作、心理、关系、身体、生活、精神九个维度逐项过一遍，先回答「我有什么」，再谈「我要做什么」。

用错会怎样跳过盘点直接定目标，计划会悬在自己并不具备的资源上；把九维做成打分排名，也会把盘点变成自我评判，反而看不清真实约束。

C03 / 专题

升维领导力

什么时候用同一件事反复发生、补救完过一阵又来，或者「大家都很努力，就是推不动」时。

怎么用先判断问题落在事件层、流程层还是系统层，再分清它是技术性问题，还是需要人改变习惯与关系的适应性挑战；之后按测—学—练—辅—升的闭环练。

用错会怎样把系统层的分歧当成执行不到位去追责，动作越加越重，问题照样复发；反过来把一次清楚的排期失误也当成适应性挑战，会把简单的事谈复杂。
